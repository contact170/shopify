CONSTAT Ce que fait la page actuelle

La page enchaîne sept blocs image-with-text / rich-text quasi identiques. Le résultat est lisible pour un humain patient, mais très pauvre pour une machine.

  • Aucun H1. La section main-page (qui porte le H1) est désactivée dans le template. Le premier titre est un H2 : « L'histoire de Daewoo ».
  • La page parle d'abord du groupe Daewoo (Corée du Sud, 1971, 60 pays) et seulement ensuite de Daewoo Security. Un moteur IA en déduit la mauvaise entité.
  • Aucune donnée d'identité structurée : ni Liz Invest SAS, ni Mérignac, ni Daewoo Home Connect, ni les gammes, ni le positionnement sans abonnement.
  • Aucun JSON-LD sur la page (le thème n'en génère que sur produits, collections, articles et FAQ).
  • Aucun maillage interne hors trois boutons identiques pointant tous vers le même comparateur.
  • Textes génériques : « engagement envers l'excellence », « technologies les plus avancées », « solutions les plus efficaces du marché » — non vérifiables, sans valeur SEO ni GEO.
  • Images sans ALT dans la bibliothèque Shopify, et parallaxe activée sur les six blocs.

Bonne nouvelle côté technique

Le header n'enveloppe le logo dans un H1 que sur la page d'accueil (request.page_type == 'index'). Sur /pages/a-propos, le nouveau H1 sera donc bien l'unique H1 de la page.

Animations

Trois effets seulement, tous en CSS : fadeUp 0,5 s à l'affichage du hero (déjà utilisé sur l'accueil), translation de 3 px des flèches de liens au survol, opacité des boutons au survol. Tout est neutralisé sous prefers-reduced-motion. La parallaxe des six blocs actuels est supprimée : c'est elle qui alourdit le scroll mobile.

Mobile

  • Toutes les grilles passent en une colonne ; les cartes s'empilent verticalement.
  • Boutons pleine largeur, hauteur de frappe ≥ 48 px.
  • H1 en clamp(32→44px) : lisible sans scroll dès l'ouverture.
  • Visuel hero recadré en 4:3 plutôt qu'en 21:9.
  • Aucun débordement horizontal : le seul élément large (tableau de compatibilité) devient une liste.
  • La maquette est pilotée par container queries : la bascule Desktop/Tablette/Mobile de l'aperçu reflowe réellement la page.

Accessibilité

  • Contrastes : blanc sur #0b1e4a ≈ 14:1 ; #545e78 sur blanc ≈ 6,4:1 ; bleu #1a4fab sur blanc ≈ 6,7:1. Le cyan ne sert jamais à porter du texte sur fond clair.
  • :focus-visible visible sur tous les liens et boutons.
  • Structure sémantique : header, section, article, dl, address, details.
  • Icônes décoratives en aria-hidden="true" ; ancres descriptives, aucun « En savoir plus ».

Performance

  • Une seule section Liquid, un seul bloc <style> scopé — pas de duplication de CSS, aucune librairie JS.
  • Images servies par le CDN Shopify en image_url: width + srcset, format WebP automatique.
  • width/height déclarés partout et aspect-ratio en CSS : aucun CLS.
  • loading="lazy" + decoding="async" sous la ligne de flottaison ; visuel hero en fetchpriority="high".
  • Suppression de la parallaxe et du compteur animé : moins de JS exécuté qu'aujourd'hui.

Ce qui rend la page lisible par une IA

  • Le premier bloc de texte contient les cinq faits d'identification : marque, produits, secteur, exploitant, ville.
  • La fiche d'identité est une liste de définitions clé/valeur, pas une prose.

  • Densité de mots-clés maîtrisée : « sans abonnement » apparaît 7 fois sur ~1 100 mots, toujours dans une phrase informative.

ÉTAPE 2 Comment l'intégration se déroulera

Rien de tout cela ne démarre avant votre validation.

  1. Une seule nouvelle section sections/page-a-propos-daewoo.liquid : balisage, CSS scopé, JSON-LD et réglages éditables dans le personnalisateur de thème. Aucun fichier partagé n'est modifié — donc aucun risque pour les autres pages.
  2. Le template templates/page.a-propos.json est réécrit pour ne contenir que cette section. Header, footer, barre d'annonces et mega-menus restent intacts. Aucun autre template n'est touché.
  3. Title et meta description mis à jour sur la page Shopify (métachamps global.title_tag / global.description_tag).
  4. Livraison sur un thème de préversion (duplicata du thème publié), pour que vous validiez le rendu réel desktop / tablette / mobile avant toute publication. La mise en ligne reste un geste que vous déclenchez.
  5. Le code est aussi versionné sur la branche claude/daewoo-about-page-redesign-qdigpx du dépôt.

Un choix technique à faire

Le dépôt Git ne contient qu'une archive d'export du thème (18 mai 2026), pas les fichiers du thème en clair. Deux options pour l'étape 2 : (a) j'écris directement les fichiers sur un thème de préversion via l'API Shopify — le plus rapide et le plus sûr ; (b) je livre les fichiers dans le dépôt et vous les poussez via Shopify CLI ou l'intégration GitHub. L'option (a) est recommandée.
